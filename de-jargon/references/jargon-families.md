# 黑话的成因、判定与还原

## 一、这些词是怎么来的

它们有一个共同来源：**把英文技术隐喻里的单个名词，当成一个概念直译进来**。

`slot` 在英文里是个具体物件（主板上的插槽），说 "connection slot" 时听者脑子里有画面。
直译成「连接槽位」之后，具体物件消失了，只剩一个空壳名词，读者拿不到任何新信息。

同类：
- `gate` → 「门禁 / 门」：英文里 gate 是水闸、闸机，有物理形态；中文「门禁」被读成"门锁系统"，与"准入校验"脱钩
- `thaw` → 「解冻」：英文里 frozen/thaw 是状态机的一对，中文「解冻」容易被读成冰箱或账号解封
- `converge` → 「收口 / 收敛」：英文里 converge 是数值逼近；中文「收口」是缝纫术语，出现在架构文档里纯属错位
- `narrow` → 「收窄」：英文 narrow the scope 是"缩小范围"；「收窄」在中文里多用于差距、通道
- `slice` → 「切片」：英文 vertical slice 是敏捷术语，time slice 是调度术语；中文「切片」第一联想是医学病理

**共同点**：这些词在中文里都有另一个更强的本义。读者每次遇到都要先做一次"这不是字面意思"的转换，读起来卡顿，而且转换结果往往不唯一。

## 二、判定：三条测试

不要靠"感觉像黑话"下判断。用这三条，可复现。

### 测试 1：落地测试（能否指向一个代码实体）

问：这个词能不能指向**一个具体的函数、字段、状态值、异常、协议字段、配置项**？

- 「启动时做权限门禁校验」→ 指不出。哪一步？校验签名？查 ACL？读配置开关？→ 黑话
- 「启动时校验客户端签名，失败则拒绝连接」→ 指向 `verify_signature()`。→ 合格

### 测试 2：反义测试（状态机是否成立）

问：这个词的**反义词在系统里是否存在且可命名**？

`解冻` 预设了一个 `冻结` 状态。如果代码里没有 frozen/suspended 这个状态，也没有进入该状态的路径，那"解冻"就是在描述一个不存在的状态转换。→ 黑话

同理 `收口` 预设了"口"（一个敞开的边界），`闭环` 预设了"环"（一个回路）。系统里如果没有这个边界或回路，词就是空的。

### 测试 3：删除测试（删掉后信息是否损失）

问：删掉这个词，句子传达的技术信息减少了吗？

- 「两个待定问题已在 v1.3.3 收口」← 删掉「收口」只剩"问题已定"，信息没少 → 它是修辞，不是信息
- 「扫描→隔离→恢复的完整流程可跑通」← 这里"完整流程"是信息，不能删

**通过不了测试 3 的词，一律改。这是最高频的情况。**

## 三、一词多义：必须先拆再改

这是最容易出错的地方。**黑话最大的危害不是难听，是一个词盖住了好几种不同机制**。直接换同义词会换错。

遇到这些词，先问"它在这里指哪一种"，再动笔。

| 词 | 可能是 | 分别的写法 |
|---|---|---|
| 门禁 | ① 身份鉴权 ② 功能开关 ③ 前置参数校验 ④ 准入策略（白名单/黑名单） | ① 校验客户端签名 ② 检查 `feature_x_enabled` ③ 校验 `path` 非空 ④ 只允许 `releases/` 下的映像 |
| 兜底 | ① 默认值 ② 异常捕获后的降级返回 ③ 超时/重试耗尽后的失败返回 ④ 备用数据源 ⑤ UI 的保底显示 | ① 缺省取 0 ② `catch` 后返回上次快照 ③ 三次重试后返回 `kTimeout` ④ 本地库缺失时读内置基线库 ⑤ 无数据时显示"—" |
| 闭环 | ① 端到端能跑通 ② 有回滚路径 ③ 有监控告警 ④ 状态机所有转移都有处理 | 逐条写明是哪一种，不要写"闭环" |
| 落地 | ① 代码已写 ② 已合入主干 ③ 已部署到目标机 ④ 已通过验证 ⑤ 已写进文档 | 直接说完成到哪一步 |
| 对齐 | ① 两边字段名相同 ② 两边取值域相同 ③ 两边行为一致 ④ 文档与代码同步 | ① 字段名统一为 `threat_name` ② `result` 取值同为 `quarantined/deferred` |
| 链路 | ① 一次调用的完整路径 ② 数据流转 ③ 一条网络连接 | 写明起点和终点：「UI → IPC → 服务进程 → 引擎」 |
| 收口 | ① 收尾完成 ② 合并到主干 ③ 决策已定 | 直说 |
| 切片 | ① 分片传输 ② 分批处理 ③ 按维度取子集 ④ 敏捷垂直切片 | 直说哪种 |
| 沉淀 | ① 写成文档 ② 抽成公共库 ③ 记进知识库 | 直说 |

**判断规则：如果一个词你能拆出两种以上含义，就必须拆 —— 说明它本身没有信息量。**

## 四、族谱与还原方向

### gate 族（门禁 / 门 / 卡口）
还原成动作：「校验」「拦截」「拒绝」。带上失败后的行为。
- ✗ 发布门 / 质量门 / 权限门禁
- ✓ 发布前跑回归用例；失败则中止
- ✓ 合并前过 `clang-tidy`，有 error 即阻断

### state 族（解冻 / 预热 / 冷热）
只保留有真实状态机的。`冷启动`、`热路径` 是真术语（cache cold/warm），保留。
`解冻` 只在系统里确有 frozen 状态时可用，且必须写明从哪个状态恢复。

### spatial 族（槽 / 槽位 / 咬合 / 锚点 / 骨架 / 正交 / 孪生）
这一族最容易残留，因为英文里它们都是很自然的比喻。
- 「槽位」→ 说清容器和位置：`m_connections[3]`、第 3 个空闲连接
- 「咬合」→ 对接，并写明两侧分别是什么
- 「骨架」→ 结构 / 待填充的部分；但 `骨架屏`（UI skeleton）是真术语
- 「正交」→ 互不影响 / 可独立变更；数学语境（正交矩阵）保留
- 「孪生」→ 副本；但 `数字孪生` 是行业术语

### flow 族（收口 / 收窄 / 收敛 / 收束 / 归一 / 拍平 / 拉齐 / 对齐）
全是"把东西弄成一致或弄完"的不同说法，但英文原词各不相同。中文全糊成一片。
一律换成具体动作：`统一为 X` / `合并到 Y` / `只处理 Z` / `展平成一层`。

注意 `对齐` 的正当用法只有 GUI 布局（左对齐、居中对齐），扫描器已白名单处理。

### buzz 族（落地 / 闭环 / 沉淀 / 抓手 / 赋能 / 颗粒度 / 拉通 / 打通 / 卡点 / 断点 / 心智 / 反哺 / 抽离 / 盘活）
来自互联网公司内部话术，特点是**用管理动作替代技术描述**。
「落地」→ 已实现 / 已部署；「赋能」→ 使 X 能够 Y；「颗粒度」→ 精度 / 精确到 N 秒。

### pseudo 族（三/四/五道防线、双保险、双链路）
用数量冒充严谨。要么逐条列出，要么删掉数字。

## 五、真术语白名单（不要改）

这些看着像黑话，但是有唯一、可验证的含义：

> 幂等、原子性、序列化、反序列化、超时、重试、退避、熔断、限流、降级、灰度、埋点、
> 事务、隔离级别、死锁、竞态、内存屏障、探针、心跳、租约、快照、回滚、背压、
> 水位线（流处理 Flink watermark）、状态机、原子操作、端到端、水平/垂直扩展、
> 冷启动、热路径、脏读、写放大、尾延迟、断点续传、归一化、数字孪生、骨架屏、垂直切片

判据：**这个词能否对应到一个有明确定义、可被验证或可被测量的机制**。能，就是术语。

## 六、灰度地带：需要问用户的情况

以下几类不要自作主张，遇到就说明情况再改：

1. **用户自己的口头习惯**。有人就是习惯说"兜底"，且团队都懂。改不改要问。
2. **行业既有译名**。`灰度` 在发布语境里已是通用译名，`背压` 是 backpressure 的标准译法。虽然也算外来比喻，但改了反而不专业。
3. **产品/业务里的专有名词**。如果有「解冻」这个功能名（账号解冻），它就是名词，不是黑话。
4. **引用的原话**。别人文档、issue、会议记录里的原句，改动会失真 —— 只标注，不改。
